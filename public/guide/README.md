# 사용 가이드 화면 사진

첫 접속 가이드 팝업(`src/components/OnboardingGuide.tsx`)이 여기 있는 파일을 씁니다.
파일이 없으면 자리표시("화면 사진 준비 중")가 대신 뜹니다.

| 파일 | 어떤 화면 |
|---|---|
| `step-1-overview.webp` | 서울 전체가 격자 색으로 칠해진 첫 화면 |
| `step-2-grid.webp` | 격자 하나를 클릭해 오른쪽 상세 패널이 열린 화면 |
| `step-3-indicator.webp` | 지도 지표를 `녹지율`로 바꿔 지도 색이 달라진 화면 (왼쪽 목록 쪽으로 잘라냄) |
| `step-4-simulation.webp` | 정책 시나리오 + 직접 시뮬레이션 (오른쪽 패널 쪽으로 잘라냄) |

## 다시 찍기

**화면이 바뀌면 사진이 거짓말이 됩니다.** UI를 고쳤으면 다시 찍으세요.
손으로 찍지 말고 아래 두 줄로 돌리면 크기·자르는 위치가 매번 같습니다.

```bash
node scripts/capture-guide-shots.mjs
python3 scripts/guide-shots-to-webp.py
```

- 개발 서버(`npm run dev`)와 백엔드(8000)가 떠 있어야 합니다.
- macOS에 이미 있는 Chrome을 헤드리스로 띄웁니다. puppeteer/playwright는 넣지 않았습니다
  (브라우저를 또 내려받게 됩니다).
- 1440x900을 **3배 해상도**로 찍고, 단계별로 잘라낸 뒤 **1600x1000 WebP(화질 85)**로 저장합니다.
- 팝업에서 745px 남짓으로 보이므로 2.1배쯤 담아두는 셈입니다. 고해상도 화면에서도 또렷합니다.
- 자르는 위치는 `scripts/guide-shots-to-webp.py` 의 `JOBS` 에 화면 비율(0~1)로 적혀 있습니다.

## ⚠️ PNG를 그대로 넣지 마세요

- 스크린샷 PNG는 장당 수 MB입니다. 위 스크립트가 WebP로 바꾸고 PNG는 지웁니다.
- geojson과 달리 **이미지는 gzip으로 줄지 않습니다**(이미 압축된 형식). 파일 크기를
  줄이는 것 말고는 방법이 없습니다.
- 초기 로딩을 2.3초 → 0.6초로 줄여놨는데, 큰 이미지 몇 장이면 그 이득이 사라집니다.
  지금 4장 합계는 약 540KB이고, 팝업에서 한 번에 한 장씩만 받아옵니다.

직접 만든 사진을 넣을 때도 **16:10**으로 맞추세요. 팝업의 사진 칸이 그 비율이라
(`object-fit: cover`) 다른 비율은 가장자리가 잘립니다.
