# 건물 비율(building_ratio) 위성 기반 보정

작성일: 2026-07-20

## 1. 문제 — "건물이 있는데 건물비율이 0%"

지도에는 건물이 빽빽한데 대시보드의 `building_ratio`가 **0%**로 뜨는 격자가 많다.
특히 **용산구**에서 심하다(사용자 제보 `11170_00967` 등).

## 2. 원인 — 서로 다른 두 데이터 출처

| 지표 | 출처 | 성격 |
|---|---|---|
| `building_ratio`, `road_ratio` | **VWorld 벡터**(건물·도로 도형) | 공개 건물 도형이 없으면 0 |
| `built_surface_ratio`, `impervious_ratio` | **위성(Earth Engine)** | 실제 지표면(건물+도로+포장)을 봄 |

- 데이터 확인: `built_surface_ratio == impervious_ratio` (서울 64,573격자 **100% 동일**).
- **위성은 "건물 바닥이 있다"는데 VWorld엔 건물·도로가 0**인 격자 = 벡터 누락 정황.

### 규모 (서울 64,676 격자 기준)
- `building_ratio == 0`: 23,140개(35.8%). 대부분은 산·공원·하천이라 **정상**.
- "위성 지표면>30% 인데 building=0 & road<5%"(누락 정황): **1,997개(3.1%)**.
  - 구별 1위 **용산(11170) 240개(10.3%)**, 2위 강서(11500) 7.3%, 3위 성동(11200) 5.4%.
- 예시 `11170_00967`: 위성 지표면 42%인데 building 0·road 0 → 명백한 누락.

### 왜 용산이 최악인가(추정)
용산 미군기지 등 **군사·공공 시설 건물이 VWorld 공개 건물 레이어에서 빠진** 정황이 크다.

## 3. 보정 계수의 근거 (왜 0.15, 0.56)

```python
NO_BUILDING_RATIO = 0.02  # building_ratio가 이 미만이면 사실상 건물 없음(누락 후보)
BUILT_UP_MIN = 0.15       # 위성 지표면이 이 이상이면 "건물 있음"으로 본다
BUILT_TO_BUILDING = 0.56  # 위성지표면 → 건물비율 추정 계수
```

- **`NO_BUILDING_RATIO = 0.02`**: 기존 파이프라인이 "사실상 건물 없음"(산·공원·하천)으로 쓰던 기준을 재사용. 이 값 이하 격자만 누락 후보로 본다.
- **`BUILT_UP_MIN = 0.15`**: 위성 지표면이 15% 미만이면 공원 가장자리·하천변 같은 **진짜 빈 셀**일 수 있어 보정하지 않는다(없는 건물을 지어내지 않기 위한 보수적 하한). 판단 기준값.
- **`BUILT_TO_BUILDING = 0.56`** (데이터 기반): 위성 지표면엔 건물+도로+포장이 섞여 있어 그대로 쓰면 과대추정. **실제 건물 데이터가 있는 38,350개 격자**에서 `building_ratio ÷ built_surface_ratio`를 계산한 결과:
  - **중앙값 0.559(→ 0.56 채택)**, 평균 0.687, Q1 0.335, Q3 0.882.
  - 이상치에 강건한 **중앙값**을 계수로 사용.

## 4. 보정 로직 & 적용 위치

```python
# src/build_seoul_dataset.py  correct_building_ratio()
gap = (building_ratio <= 0.02) & (built_surface_ratio >= 0.15)
building_ratio_estimated = gap                       # 플래그
building_ratio[gap] = built_surface_ratio[gap] * 0.56  # 위성 기반 추정
```

- **적용 위치**: `build_seoul_dataset.py`의 `correct_building_ratio()` — **파생변수(`building_shadow_proxy` 등) 계산 직전**에 호출.
- 그래서 보정값이 **정적/시간 데이터셋 → 모델 재학습(`analyze_seoul_shap.py`) → SHAP → 대시보드(`build_seoul_dashboard.py`) → 250·500m 집계**까지 **한 값으로 일관** 전파된다.

## 5. 프론트엔드 표시

`GridDetailSidePanel.tsx`는 데이터의 `building_ratio_estimated` 플래그만 읽어:
- 라벨 `건물 비율 (추정)`, 값 앞에 `≈`,
- 하단 캡션: *"이 격자는 건물 도형(VWorld) 데이터가 없어, 위성 지표면(built-up)으로 건물 비율을 추정한 값입니다."*

## 6. 한계

- 계수 0.56은 **서울 전역 중앙값**이라 격자별 편차가 크다(Q1 0.34 ~ Q3 0.88). 개별 추정치의 정확도는 낮을 수 있어 **"추정"으로 명시**한다.
- 위성 지표면엔 도로·포장이 포함돼, 도로가 많은 셀은 과대추정 가능.
- **근본 해결**은 VWorld 건물 재수집 또는 군사·공공시설이 포함된 건물 데이터 확보.
- 250/500m는 값은 100m 보정치의 면적가중 평균으로 반영되지만, `estimated` 플래그(캡션)는 붙지 않는다.
