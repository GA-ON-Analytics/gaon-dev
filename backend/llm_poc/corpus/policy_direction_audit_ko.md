# 정책 변수 방향 점검과 단조성 제약 도입

작성: 2026-07-29 / 관련 이슈: gaon-dev#18
점검 스크립트: [`src/audit_policy_directions.py`](../src/audit_policy_directions.py)

## 왜 이 점검이 필요한가

모델이 학습하는 것과 시뮬레이션이 주장하는 것은 다르다.

| 모델이 배운 것 | 시뮬레이션이 주장하는 것 |
|---|---|
| 녹지가 **많은 격자**가 적은 격자보다 시원하다 (횡단면 비교) | 이 격자에 녹지를 **늘리면** 시원해진다 (개입 효과) |

전자를 후자로 읽으려면 교란이 없어야 하는데, 실제로는 있다. 그리고 교란이 강한 변수에서는
**방향 자체가 뒤집힌다.**

## 발견 — 알베도가 물리와 반대로 학습됐다

```
알베도 +0.05 (쿨루프)  →  평균 +0.320℃,  더워진다고 예측한 격자 68.8%
```

복사 에너지수지상 표면이 흡수하는 단파복사는 `(1-α)S↓`이므로, 반사율 α가 오르면
지표면온도는 **내려가야** 한다. 특히 타깃이 기온이 아니라 LST(지표면온도)라
이 관계는 더 직접적이다.

원인은 교란이다. 서울에서 알베도가 높은 표면은 밝은 콘크리트·아스팔트·나대지·산업용
지붕이고, 이들은 대체로 불투수면이라 실제로 뜨겁다.

| 관측 상관 (실제 온도이상 대비) | |
|---|---|
| `impervious_ratio` | +0.751 |
| **`albedo`** | **+0.346** |
| `green_ratio` | −0.587 |
| `albedo` vs `impervious_ratio` | +0.241 |

모델은 "알베도 높은 곳이 덥다"는 **관측 사실**을 정확히 학습했다. 틀린 것은 모델이 아니라
그 관계를 개입 효과로 읽어도 된다는 가정이었다.

## 전수 점검 결과 (제약 도입 전)

설명용 compact 모델 기준, 표본 3,000격자.

| 판정 | 변수 | 기대방향 격자 | 관측 상관 |
|---|---|---|---|
| 정상 | `building_ratio` | 91.3% | +0.742 |
| 정상 | `green_ratio` | 80.7% | −0.587 |
| 정상 | `ndvi` | 77.8% | −0.308 |
| 정상 | `impervious_ratio` | 77.1% | +0.751 |
| 혼재 | `floor_area_ratio_proxy` | 56.3% | +0.346 |
| 혼재 | `zoning_green_ratio` | 52.9% | −0.664 |
| 혼재 | `road_ratio` | 48.3% | +0.350 |
| 혼재 | `nearest_park_distance_m` | 41.8% | −0.502 |
| **역방향** | **`albedo`** | **29.6%** | +0.346 |
| **역방향** | **`park_area_within_500m`** | **17.6%** | +0.353 |

`park_area_within_500m`도 같은 문제다. 서울 공원은 도심 고밀도 지역에 조성되는 경우가
많아 사실상 "도심다움"의 대리 지표가 됐다. `nearest_park_distance_m`이 −0.502
(공원에서 멀수록 시원)인 것도 같은 이야기다 — 공원에서 먼 곳은 외곽·산지다.

### 배포 모델은 더 나빴다

위 표는 설명용 compact 모델(`min_samples_leaf=20`) 기준이다. **실제 배포되는 패널
모델(`min_samples_leaf=8`, 700트리)은 방향이 훨씬 더 흔들린다.**

| 변수 | 배포 패널 모델 | compact 모델 |
|---|---|---|
| `albedo` | **36.3%** | 28.9% |
| `building_ratio` | **63.5%** | 92.2% |
| `impervious_ratio` | **61.1%** | 76.4% |
| `green_ratio` | **57.4%** | 80.7% |
| `ndvi` | **55.7%** | 78.3% |

`green_ratio`가 57.4%라는 것은 **격자 10개 중 4개에서 "녹지를 늘리면 더워진다"** 고
답한다는 뜻이다. 더 잘게 쪼개진 트리가 국소 노이즈를 그대로 학습한 결과다.

## 해결 — 단조성 제약

### 재학습만으로는 안 고쳐진다

교란은 데이터에 있지 알고리즘에 있지 않다. 알고리즘을 RandomForest →
HistGradientBoosting으로 바꿔 학습해도 `albedo` 37.1%, `park_area` 2.5%로 똑같이
역방향이었다.

### sklearn RandomForest가 `monotonic_cst`를 지원한다

`sklearn 1.9` 기준. 모델 종류를 바꿀 필요가 없으므로 `estimators_`가 유지되고,
`delta_std` / `direction_confidence`(gaon-dev#17) 계산도 그대로 쓸 수 있다.

제약은 `src/train_dongdaemun_grid_spatial_effect.py`의 `MONOTONIC_CONSTRAINTS`에
정의하고, `train_seoul_model.py`(배포 모델)와 `analyze_seoul_shap.py`(설명·시뮬레이션
모델) 양쪽이 같은 값을 참조한다. 두 모델의 제약이 어긋나면 지도 값과 시뮬레이션 결과의
방향이 달라지므로 반드시 함께 가야 한다.

```python
MONOTONIC_CONSTRAINTS = {
    "green_ratio": -1,       # 식생 증발산·차광
    "ndvi": -1,              # 식생 활력
    "albedo": -1,            # 반사율↑ → 흡수 단파복사 (1-a)S ↓
    "impervious_ratio": 1,   # 인공 포장면 축열
    "building_ratio": 1,     # 건물 축열·통풍 저해
}
```

**방향이 물리적으로 확실한 것만 건다.** 제약을 많이 걸수록 성능 대가가 커지고,
`park_area_within_500m`처럼 교란이 강한 변수는 제약하면 모델이 변수를 아예 포기한다
(제약 실험에서 99.4% 무변화). 그런 변수는 제약 대신 정책 레버에서 빼는 게 맞다.

### 결과 (실제 배포 학습 구성, 패널 782,702행)

| 변수 | 제약 없음 | 제약 적용 | 반대 방향 |
|---|---|---|---|
| `green_ratio` | 57.4% | **99.9%** | 42.6% → **0%** |
| `building_ratio` | 63.5% | **99.8%** | 36.4% → **0%** |
| `ndvi` | 55.7% | **99.4%** | 44.3% → **0%** |
| `impervious_ratio` | 61.1% | **99.0%** | 38.9% → **0%** |
| `albedo` | 36.3% | **89.8%** | 63.7% → **0%** |

효과 크기도 커졌다. 방향이 뒤섞여 서로 상쇄되던 것이 정리됐기 때문이다.

```
green_ratio       -0.159 → -0.195 ℃
ndvi              -0.143 → -0.205 ℃
impervious_ratio  +0.242 → +0.382 ℃
building_ratio    +0.167 → +0.510 ℃
albedo            +0.299 → -0.040 ℃   ← 부호 반전
```

### 성능 대가

| split | 제약 없음 | 제약 | 차이 |
|---|---|---|---|
| `grouped_by_grid` R² | 0.8326 | **0.7861** | −0.047 |
| `grouped_by_grid` MAE | 1.3853 | **1.5633** | +0.178 |
| `leave_one_gu_out` R² | 0.7744 | **0.7552** | −0.019 |
| `leave_one_gu_out` MAE | 1.6220 | **1.6743** | +0.052 |

**`leave_one_gu_out` 하락이 `grouped_by_grid`의 40% 수준이라는 점이 중요하다.**
제약이 깎아낸 것은 주로 "같은 구 안에서의 국소 패턴 암기"이고, 처음 보는 구에 대한
일반화 능력은 훨씬 덜 손상됐다. 정책 시뮬레이터는 "이 구에서 배운 것을 저 구에 적용"하는
도구이므로 후자가 본질이다.

참고로 이 모델의 MAE에는 **약 0.9℃의 원리적 하한**이 있다(격자 내 LST anomaly 변동
1.125℃). R² 일부는 어차피 노이즈를 맞히던 것이다.

### 부수 효과 — 두 모델이 정렬됐다

| | compact (시뮬레이션용) | 배포 모델 | 차이 |
|---|---|---|---|
| 제약 후 | 0.7828 | 0.7861 | **0.0033** |
| 제약 전 | 0.8161 | 0.8326 | 0.0165 |

간격이 5배 좁아졌다. 하이퍼파라미터(`min_samples_leaf` 8 vs 20)가 달라도 같은 물리
방향으로 묶이니 결과가 수렴한다. 지도에 보이는 값과 우측 시뮬레이션 값이 더 일관되게 나온다.

## 남는 한계 — 반드시 함께 읽을 것

**단조성 제약은 "물리적으로 말이 되는 답"을 만들지 "검증된 답"을 만들지 않는다.**

- **방향은 확실하다.** 복사 에너지수지는 확립된 물리이고, 데이터가 교란돼 못 뽑아낼 뿐이다.
  제약은 임의적 개입이 아니라 정당한 사전지식 주입이며, 오히려 제약 없는 모델이 틀린 상태다.
- **크기는 불확실하다.** 알베도 +0.05가 몇 도를 낮추는지는 이 데이터로 정할 수 없다.
  제약 후 −0.040℃로 작게 나온 것도 실제 물리적 크기라기보다 교란된 데이터에서 모델이
  뽑아낼 수 있는 한계일 가능성이 크다. **쿨루프 시나리오에서 이 숫자를 절대값으로 쓰면 안 된다.**
- **인과 검증은 여전히 불가능하다.** 정책 변수가 패널에서 시간에 대해 100% 고정이라
  반사실 데이터가 없다. 같은 격자에서 녹지가 실제로 변한 사례가 0건이다.

## 재생성 소요 시간 (실측)

제약을 걸면 **SHAP 계산이 크게 느려진다.** 트리의 분할 구조가 달라져 TreeExplainer의
경로 탐색 비용이 늘어나기 때문이다.

| 단계 | 제약 전 | 제약 후 |
|---|---|---|
| `train_seoul_model.py` | ~45분 | ~45분 (비슷) |
| `analyze_seoul_shap.py` | ~10분 | **~110분** |
| 대시보드 재생성 3단계 | ~10분 | ~10분 |

전체 재생성에 **약 3시간**을 잡아야 한다. 백그라운드로 돌리고 진행률
(`SHAP N/64574`)을 확인하는 것이 좋다.

## 앞으로

- 모델·feature를 건드릴 때마다 `python src\audit_policy_directions.py`를 돌려 회귀를 확인한다.
- 제약을 건 변수인데 '반대'가 0%가 아니면 제약이 적용되지 않은 것이다.
- 혼재 변수(`road_ratio`, `zoning_green_ratio`, `floor_area_ratio_proxy`,
  `nearest_park_distance_m`)에 제약을 추가할지는 성능 대가를 다시 재고 판단한다.
- `park_area_within_500m`·`nearest_park_distance_m`은 정책 레버에서 제외한 상태다
  (대시보드 표시용으로만 남는다).
