# 시뮬레이션 불확실성 — 무엇이 문제였고 무엇이 아니었나

작성: 2026-07-29 (재작성) / 관련: gaon-dev #11, #17, #18
재현: `python src\analyze_simulation_snr.py`

> **이 문서는 한 번 다시 썼다.** 초판은 "격자 95%에서 시뮬레이션이 신뢰 불가"라고 결론지었으나,
> 그 판단에 쓴 지표(`delta_std`)가 추정오차의 8.3배 과대평가라는 것이 이후 실측으로 밝혀졌다.
> 아래는 정정된 내용이다.

## 요약

| 처음 생각한 문제 | 실제 |
|---|---|
| 모델이 자기 답에 확신이 없다 (SNR 0.42) | ❌ **측정 지표가 틀렸다.** 실제 SNR은 3.20 |
| MAE 1.385℃가 효과 0.36℃보다 크다 | ❌ MAE는 차분 평가 지표가 아니다 |
| — | ✅ **일부 변수는 방향 자체가 물리와 반대였다** (별도 이슈 #18에서 해결) |

## MAE는 차분 평가 지표가 아니다

"모델 MAE가 1.385℃인데 시뮬레이션 효과는 0.36℃라 무의미하다"는 직관적 우려가 있으나
**이 비교는 성립하지 않는다.** 시뮬레이션은 *같은 격자·같은 모델*의 차분이라 격자별
계통오차(지역 편향, 미반영 요인)가 baseline과 시나리오 양쪽에 동일하게 실려 상쇄된다.
MAE는 절대 예측오차이므로 차분에 적용하면 과대평가다.

이 지적 자체는 이슈 #11에서 이미 반영돼 `delta_std`(트리별 차분의 산포)가 추가됐다.

## `delta_std`도 추정오차가 아니다 (#17)

`delta_std`가 재는 것은 **"트리 하나를 뽑았을 때 답이 얼마나 다른가"** 이고,
사용자에게 보여주는 값은 **300개 트리의 평균**이다. 이 둘은 다르다.

RandomForest는 배깅과 피처 무작위(`max_features=0.33`)로 트리를 **일부러 다르게** 만든다.
트리 간 불일치가 큰 것은 설계된 특성이지 예측이 불안정하다는 뜻이 아니다. 게다가 개입이
작으면 상당수 트리가 분할 임계값을 넘지 못해 `delta = 0`을 반환하는데(녹지 +5%p에서 약 40%,
연동 없이 녹지만 +5%p면 67%), 이 계단함수 양자화 잡음은 평균에서 상쇄된다.

### 실측 — 데이터 부트스트랩 8회 재학습

격자 데이터를 부트스트랩해 숲을 8번 새로 학습하고, 같은 격자·같은 시나리오의 변화량이
얼마나 흔들리는지 직접 측정했다.

```
-0.369, -0.372, -0.373, -0.379, -0.380, -0.384, -0.388, -0.393
```

| 지표 | 값 |
|---|---|
| 효과 \|delta\| 평균 | 0.493℃ |
| **`delta_std` (당시 UI에 쓰던 값)** | **1.099℃** |
| **재학습 간 표준편차 (진짜 추정오차)** | **0.132℃** |
| 과대 배율 | **8.3배** |
| SNR (효과/오차) | 0.38 → **3.20** |
| SNR > 1 인 격자 비율 | 3.8% → **91.0%** |

유효 독립 트리 수 = (1.099/0.132)² ≈ **69개** (300개 중). 트리가 서로 상관돼 있어 √300만큼
다 줄지는 않지만, 트리 산포를 그대로 쓰는 것과는 자릿수가 다르다.

`min_samples_leaf`를 20 → 5로 낮추면 추정오차가 0.234℃로 **늘어** SNR이 3.20 → 1.93으로
나빠진다. 현재 하이퍼파라미터가 더 낫다.

### 해결 (#17)

UI에서 `트리 간 변화량 편차 N℃` 표기를 없애고 **`저감 가능성 N%`** (트리들의 방향 동의율)로
교체했다. `delta_std`는 API 응답에 남기되 오차막대로 쓰지 말라는 주석을 달았다.

## 진짜 문제는 따로 있었다 (#18)

정밀도(같은 질문에 같은 답을 하는가)는 확보돼 있었다. 문제는 **일부 변수에서 답의 방향
자체가 물리와 반대**였다는 것이다.

```
알베도 +0.05 (쿨루프)  →  평균 +0.320℃,  더워진다고 예측한 격자 68.8%
```

배포 모델 기준으로는 `green_ratio`조차 방향 일치율이 57.4%였다 — 격자 10개 중 4개에서
"녹지를 늘리면 더워진다"고 답했다.

단조성 제약을 도입해 해결했다. 자세한 내용은
[policy_direction_audit_ko.md](policy_direction_audit_ko.md) 참고.

| 변수 | 제약 전 | 제약 후 | 반대 방향 |
|---|---|---|---|
| `green_ratio` | 57.4% | 99.9% | 42.6% → **0%** |
| `albedo` | 36.3% | 89.8% | 63.7% → **0%** |

## 여전히 남는 한계 — 인과 검증 불가

**정책 변수가 패널에서 시간에 대해 100% 고정이다.**

```
782,702행 / 64,574격자 / 35개 날짜

격자 내 고유값 개수:
  green_ratio        1.00개   시간에 따라 변하는 격자   0.0%
  impervious_ratio   1.00개                          0.0%
  ndvi               1.00개                          0.0%
  albedo             1.00개                          0.0%
  lst_daily_anomaly 12.12개                        100.0%
```

패널 구조로 보이지만 시간 차원은 타깃에만 있다. **같은 격자에서 녹지가 실제로 변한 사례가
0건**이므로, "녹지를 5%p 늘렸더니 온도가 얼마나 변했다"는 관측이 존재하지 않는다.

| | 모델이 배운 것 | 시뮬레이션이 주장하는 것 |
|---|---|---|
| 질문 | 녹지가 **많은 격자**가 시원한가? | 이 격자에 녹지를 **늘리면** 시원해지는가? |
| 데이터 | ✅ 있음 | ❌ 없음 |

따라서 **`delta_C`의 MAE/RMSE는 원리적으로 계산할 수 없다.** 정답 레이블이 없다.
단조성 제약도 "물리적으로 말이 되는 답"을 만들지 "검증된 답"을 만들지 않는다.

### 타깃 노이즈 — 못 줄이는 부분

```
LST anomaly 전체 표준편차   4.416℃
  격자 간 (모델이 설명 가능)  4.406℃   ← 93.9%
  격자 내 (날씨·관측 노이즈)  1.125℃   ← 설명 불가
```

같은 격자를 35일에 걸쳐 관측하면 날짜마다 anomaly가 ±1.1℃ 흔들린다. 구름·촬영시각·풍향
같은 것들이다. **모델을 아무리 잘 만들어도 MAE가 약 0.9℃ 밑으로는 안 내려간다.**

## 실무적 함의

| 표현 | 가능 여부 |
|---|---|
| "이 격자에 녹지 5%p 늘리면 0.63℃ 내려간다" | ⚠️ 정밀도는 있으나 인과 검증 안 됨 |
| "동대문구 전체 평균 0.63℃ 저감 예상" | ✅ 집계 수준에서 더 방어 가능 |
| 우선순위 지도의 **순위(ordering)** | ✅ 가장 방어 가능한 사용법 |
| 쿨루프 효과의 **절대 수치** | ❌ 크기는 이 데이터로 정할 수 없다 |

**"정확한 온도를 보장하는 시스템"보다 "정책 시나리오 간 상대 효과 비교, 냉각 가능성이
높은 지역 우선순위 추천, 정책 후보 지역 탐색"으로 목적을 잡는 것이 현실적이다.**

## 아직 안 한 검증

- **매칭 준실험** — 고도·건물·하천거리가 비슷하고 녹지만 다른 격자쌍을 매칭해 온도차 비교.
  인과 주장에 가장 직접적인 근거를 준다. 지금 데이터로 가능하다.
- **문헌 대조** — 도시 녹화·쿨루프 냉각 효과의 기존 연구값과 자릿수가 맞는지 확인.
  특히 알베도는 제약 후에도 효과가 −0.028℃로 작아 크기 검증이 필요하다.
- **순위 안정성** — 트리 부트스트랩으로 우선순위 상위 격자가 얼마나 흔들리는지.
  "순위 중심으로 쓰자"는 결론이 실제로 성립하는지 검증한다.
